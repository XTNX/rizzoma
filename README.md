# RIZZOMA — лендинг и Telegram Mini App

Одна и та же страница работает двумя способами:

- **как обычный сайт** — реферальные ссылки вида `?ref=КОД`;
- **как Mini App внутри Telegram** — разворачивается на весь экран, отдаёт оплату
  системной кнопке MainButton, закрывается системной BackButton, добавляет тактильный
  отклик, синхронизирует узел через `CloudStorage` и читает диплинк `?startapp=КОД`.

Определение режима автоматическое (`WebApp.platform !== 'unknown'`), отдельной сборки нет.

---

## Состав

| Файл | Что это |
|---|---|
| `index.html` | всё приложение: вёрстка, генеративная сцена, реферальная механика, мок-чекаут |
| `config.js` | конфигурация деплоя: бот, short name приложения, адрес бэкенда |
| `logo.svg` | логотип; из этого же контура строится ядро генеративной сцены |
| `brand-spec.md` | дизайн-система: токены, типографика, motion |
| `bot/` | референс-бэкенд: диплинки, реферальный граф, секция «Свои» |

Сборки нет — статика кладётся на хостинг как есть.

## 1. Публикация статики

Нужен **HTTPS** — Telegram не открывает Mini App по http.

Подойдёт любой статический хостинг: GitHub Pages, Netlify, Vercel, Cloudflare Pages,
nginx на своём сервере. Выложить нужно `index.html`, `config.js`, `logo.svg`.

Локальная проверка перед публикацией:

```bash
npx serve M:/rizzoma/site
```

## 2. Регистрация в BotFather

1. `/newbot` → имя и username → сохрани токен.
2. `/newapp` → выбери бота → название, описание, иконку **640×360**, **short name**
   (например `fest`) → на запрос Web App URL укажи адрес статики из шага 1.
3. Ссылка на приложение: `https://t.me/<бот>/<short name>`
   Реферальная: `https://t.me/<бот>/<short name>?startapp=КОД`

Дополнительно: `/setmenubutton` — чтобы приложение открывалось кнопкой рядом с полем ввода.

## 3. Настройка `config.js`

```js
window.RIZZOMA_CONFIG = {
  bot: 'rizzoma_fest_bot',   // username без @
  app: 'fest',               // short name из /newapp
  apiBase: '',               // адрес бэкенда, пока пусто — секция «Свои» демонстрационная
  crewDemo: true
};
```

Как только заполнены `bot` и `app`, кнопки «Поделиться» отдают ссылку
`t.me/бот/апп?startapp=КОД` вместо `?ref=КОД` — то есть открывают приложение, а не браузер.

## Секреты

`BOT_TOKEN` даёт полный контроль над ботом — в репозиторий он не попадает никогда,
даже в приватный. Место токена — переменные окружения хостинга бэкенда;
локально он лежит в `bot/.env`, который закрыт `.gitignore`.
В репозитории есть только `bot/.env.example` с плейсхолдерами.

Если токен всё-таки где-то засветился — `/revoke` у @BotFather, затем `/token` за новым.

В статике (`index.html`, `config.js`) секретов нет и быть не должно:
всё, что там лежит, видно любому посетителю через «просмотр кода страницы».

## 4. Бэкенд (нужен только для живой секции «Свои»)

```bash
cd bot
cp .env.example .env      # заполни BOT_TOKEN и APP_URL
npm install
npm start
```

Затем пропиши в `config.js` → `apiBase: 'https://адрес-бэкенда'`.

## Секция «Свои» — что здесь возможно, а что нет

**Невозможно:** получить адресную книгу пользователя. У Telegram нет такого метода
ни для Mini App, ни для Bot API. `requestContact` тоже не решает задачу — он отдаёт
серверу *твой* номер, а не список твоих знакомых.

**Возможно и реализовано:** граф из реферальных переходов, который бот записывает сам.

| Источник | Когда доступен |
|---|---|
| твоя ветвь — кто пришёл по твоей ссылке | всегда, даже без бэкенда (локальные данные) |
| кто позвал тебя | после привязки аккаунта через бота |
| соседи по ветви — приглашённые тем же человеком | после привязки аккаунта |
| демо-контакты с пометкой `ДЕМО` | пока `apiBase` не задан |

Привязка: кнопка «Привязать через бота» открывает `t.me/<бот>?start=link_КОД`,
бот запоминает пару «аккаунт ↔ узел».

### Контракт API

Все запросы — `POST`, тело JSON, обязательное поле `initData`
(строка `Telegram.WebApp.initData`; сервер проверяет её HMAC по схеме `WebAppData`
и отвергает всё старше суток).

| Эндпоинт | Тело | Ответ |
|---|---|---|
| `/api/visit` | `{initData, ref}` | `{ok:true}` — фиксирует, по чьей ссылке открыто приложение |
| `/api/purchase` | `{initData, code}` | `{ok:true}` — отметка об оплате |
| `/api/friends` | `{initData}` | `{linked, friends:[…]}` |

Элемент `friends[]`:

```json
{ "id":"123", "name":"Ника В.", "username":"nika_void",
  "photo":"https://…", "status":"paid", "tier":2 }
```

`status`: `paid` — допуск оплачен · `node` — в сети, но без оплаты · `none` — можно позвать.

`/api/visit` вызывает само мини-приложение: параметр `startapp` до бота не долетает,
он приходит только в `initDataUnsafe.start_param`.

## Что заменить перед боевым запуском

| Сейчас | В проде |
|---|---|
| оплата — клиентская имитация (валидация Луна, тестовые карты) | `WebApp.openInvoice()` + Telegram Payments или Stars; узел засчитывается по вебхуку `successful_payment`, а не по ответу клиента |
| «БД» рефералов — `localStorage` + `CloudStorage` | сервер: атрибуция, дедупликация и анти-фрод считаются на бэкенде |
| хранилище бота — `Map` в памяти | Postgres / Redis |
| код узла выдаёт клиент | коды выдаёт сервер, клиент их только показывает |

Клиентская «БД» правится из консоли браузера — на неё нельзя вешать реальные награды.

## QA

`?devpanel=1` — панель тестирования: `+1` / `+5` рефералов, генерация тест-ссылки,
вход под чужим узлом, сброс атрибуции и полный сброс.
`?reduce=1` — статичный режим без WebGL и автоанимаций (эквивалент
`prefers-reduced-motion: reduce`).

Тестовые карты чекаута: `4242 4242 4242 4242` — успех, `4000 0000 0000 0002` — отказ.

Сценарий приёмки реферала: открыть `?ref=КОД1` (или `?startapp=КОД1`) → оплатить
картой успеха → у `КОД1` счётчик +1, шкала и тир обновляются без перезагрузки;
оплата картой отказа счётчик не двигает; повторный сабмит не создаёт вторую запись.

## Экономика

Правится в двух массивах `index.html`: `TIERS` — лестница наград,
`TICKETS` — тарифы (`price: null` показывает «уточняется»).
