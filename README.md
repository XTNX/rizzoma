# RIZZOMA — Telegram Mini App «дерево узлов»

Приложение на один экран: генеративная сеть вокруг логотипа стала **радиальным деревом
прокачки**. Скиллы не нарисованы поверх сети — каждый сидит на реальной вершине её клина,
а глубина ветвления работает как кольцо прокачки. Билеты живут в bottom sheet и доступны
в один тап, «Свои» — соседняя вкладка.

При запуске на экране только фиолетовый «неактивный» знак. Касание разворачивает сеть
кольцо за кольцом, по ней прокатывается импульс готовности — и интерфейс проявляется.

Одна и та же страница работает двумя способами:

- **как Mini App внутри Telegram** (основной сценарий) — разворачивается на весь экран,
  отдаёт оплату системной MainButton, закрывает модалки системной BackButton, добавляет
  тактильный отклик, синхронизирует узел и полученные скиллы через `CloudStorage`,
  читает диплинк `?startapp=КОД`;
- **как обычная страница в браузере** — те же жесты мышью/пальцем, ссылки вида `?ref=КОД`,
  без хаптики и системных кнопок.

Определение режима автоматическое (`WebApp.platform !== 'unknown'`), отдельной сборки нет.

## Экран и жесты

| Элемент | Поведение |
|---|---|
| Знак при запуске | единственное, что есть на экране; касание запускает развёртку сети (~2.3 с), после неё появляется интерфейс. До этого сцена на жесты не реагирует |
| Дерево | пан-зум внутри канвы (драг, колесо, пинч). Страница не скроллится нигде |
| Границы поля | знак-ядро всегда остаётся на экране: за пределом драг тормозится (overscroll) и отпускание возвращает поле обратно |
| Подписи при зуме | раскладчик проверяет пересечения: что не помещается — плавно гаснет, что освободилось — проявляется. Наложений на поле нет ни на одном масштабе; пороги закрытых узлов показываются только крупнее ×0.92 |
| Тап по узлу | окно узла: имя скилла, награда, прогресс. Скромная анимация |
| Удержание ~1 c на доступном узле | активация скилла: кольцо заполняется, нарастает хаптика; отпустил раньше — отмена без изменения состояния |
| Активация завершена | прожиг ветви от ядра до узла, частицы, фиолетовый → токсично-зелёный, микро-тряска, `notificationOccurred('success')` |
| Заблокированный узел | на удержание не реагирует, тап показывает требование «нужно ещё N» |
| Кнопка «Билеты» | bottom sheet чекаута из любого состояния дерева |
| Вкладка «Свои» | список ветви и контактов от бота; сцена на паузе |
| Знак узла в баре | тап — активация узла / копирование ссылки, **пять тапов — админка** |

Скиллы сгруппированы в три ветви (`BRANCHES`) по смыслу награды — это только группировка,
пороги и награды берутся из `TIERS` без изменений:

| Ветвь | Про что | Скиллы (порог в узлах) |
|---|---|---|
| I · **ВОЛЯ** | проходки и скидки на билеты | ПРОБИТИЕ (1), ПРОХОД (3), ОБХОД (10) |
| II · **ТЕЛО** | мерч, аксессуары, вещи, именной знак | КАПСУЛА (5), РЕЛИКТ (25), ТОТЕМ (100) |
| III · **РАЗУМ** | VIP и пожизненные бонусы | ГЛУБИНА (15), КОНТУР (40), РЕЗИДЕНТ (60), ВЕЧНАЯ ВЕТВЬ (80) |

Каждая ветвь — один луч сети (симметрия ×3, плюс зеркальные двойники как облако).
Хочешь переставить скилл в другую ветвь — правится массив `BRANCHES`, геометрия
пересчитается сама.

## 1. Публикация статики

Нужен **HTTPS** — Telegram не открывает Mini App по http.

Подойдёт любой статический хостинг: GitHub Pages, Netlify, Vercel, Cloudflare Pages,
nginx на своём сервере.

Локальная проверка перед публикацией:

```bash
npx serve M:/rizzoma/site
```

## 2. Регистрация в BotFather

1. `/newbot` → имя и username → сохрани токен.
2. `/newapp` → выбери бота → название, описание, иконку **640×360**, **short name**
   (например `fest`) → на запрос Web App URL укажи адрес статики из шага 1.
3. Ссылка на приложение: `https://t.me/<бот>/<short name>`
   Реферальная: `https://t.me/<бот>/<short name>?startapp=КОД`

Дополнительно: `/setmenubutton` — чтобы приложение открывалось кнопкой рядом с полем ввода.

## 3. Настройка `config.js`

```js
window.RIZZOMA_CONFIG = {
  bot: 'rizzoma_fest_bot',   // username без @
  app: 'fest',               // short name из /newapp
  apiBase: '',               // адрес бэкенда, пока пусто — вкладка «Свои» демонстрационная
  crewDemo: true
};
```

Как только заполнены `bot` и `app`, кнопка «Поделиться» отдаёт ссылку
`t.me/бот/апп?startapp=КОД` вместо `?ref=КОД` — то есть открывает приложение, а не браузер.

## Секреты

`BOT_TOKEN` даёт полный контроль над ботом — в репозиторий он не попадает никогда,
даже в приватный. Место токена — переменные окружения хостинга бэкенда;
локально он лежит в `bot/.env`, который закрыт `.gitignore`.
В репозитории есть только `bot/.env.example` с плейсхолдерами.

Если токен всё-таки где-то засветился — `/revoke` у @BotFather, затем `/token` за новым.

В статике (`index.html`, `config.js`) секретов нет и быть не должно.

## 4. Бэкенд (нужен только для живой вкладки «Свои»)

```bash
cd bot
cp .env.example .env      # заполни BOT_TOKEN и APP_URL
npm install
npm start
```

Затем пропиши в `config.js` → `apiBase: 'https://адрес-бэкенда'`.

## Вкладка «Свои» — что здесь возможно, а что нет

**Невозможно:** получить адресную книгу пользователя. У Telegram нет такого метода
ни для Mini App, ни для Bot API. `requestContact` тоже не решает задачу — он отдаёт
серверу *твой* номер, а не список твоих знакомых.

**Возможно и реализовано:** граф из реферальных переходов, который бот записывает сам.

| Источник | Когда доступен |
|---|---|
| твоя ветвь — кто пришёл по твоей ссылке | всегда, даже без бэкенда (локальные данные) |
| кто позвал тебя | после привязки аккаунта через бота |
| соседи по ветви — приглашённые тем же человеком | после привязки аккаунта |
| демо-контакты с пометкой `демо` | пока `apiBase` не задан |

Привязка: кнопка «Привязать через бота» открывает `t.me/<бот>?start=link_КОД`,
бот запоминает пару «аккаунт ↔ узел».

### Контракт API (не изменился)

Все запросы — `POST`, тело JSON, обязательное поле `initData`
(строка `Telegram.WebApp.initData`; сервер проверяет её HMAC по схеме `WebAppData`
и отвергает всё старше суток).

| Эндпоинт | Тело | Ответ |
|---|---|---|
| `/api/visit` | `{initData, ref}` | `{ok:true}` — фиксирует, по чьей ссылке открыто приложение |
| `/api/purchase` | `{initData, code}` | `{ok:true}` — отметка об оплате |
| `/api/friends` | `{initData}` | `{linked, friends:[…]}` |

Элемент `friends[]`:

```json
{ "id":"123", "name":"Ника В.", "username":"nika_void",
  "photo":"https://…", "status":"paid", "tier":2 }
```

`status`: `paid` — допуск оплачен · `node` — в сети, но без оплаты · `none` — можно позвать.

`/api/visit` вызывает само мини-приложение: параметр `startapp` до бота не долетает,
он приходит только в `initDataUnsafe.start_param`.

## Хранилище

| Ключ | Содержимое |
|---|---|
| `rizzoma_mock_db` | `{users:{…}, buyers:{…}, profiles:{…}, claims:{КОД:[индексы скиллов]}}` |
| `rizzoma_me` | код текущего узла |
| `rizzoma_attribution` | `{code, ts}`, TTL 30 дней |
| `rizzoma_claims` | компактное зеркало полученных скиллов: `{code, list:[…]}` |

`claims` — аддитивное расширение прежней схемы; отдельный ключ `rizzoma_claims` нужен
потому, что лимит CloudStorage — 4096 символов на ключ, и полный дамп БД туда со временем
перестаёт помещаться, а список скиллов помещается всегда.

## Что заменить перед боевым запуском

| Сейчас | В проде |
|---|---|
| оплата — клиентская имитация (валидация Луна, тестовые карты) | `WebApp.openInvoice()` + Telegram Payments или Stars; узел засчитывается по вебхуку `successful_payment` |
| «БД» рефералов и полученные скиллы — `localStorage` + `CloudStorage` | сервер: атрибуция, дедупликация, анти-фрод и выдача скиллов считаются на бэкенде |
| хранилище бота — `Map` в памяти | Postgres / Redis |
| код узла выдаёт клиент | коды выдаёт сервер, клиент их только показывает |

Клиентская «БД» правится из консоли браузера — на неё нельзя вешать реальные награды.

## QA / админка

Три входа:

1. **Кнопка `QA` в верхнем баре** — для показа заказчику прямо внутри Telegram, где
   `?admin=1` не набрать. Включается флагом `qaButton: true` в `config.js`.
   **Перед релизом поставить `false`** — кнопка исчезнет, остальные два входа останутся.
   Она нарочно выглядит служебной (красный пунктир), чтобы её не забыли убрать.
2. `?admin=1` (синоним `?devpanel=1`) — в браузере.
3. **Пять тапов по знаку узла в баре** — работает всегда, в том числе в Telegram.

Панель помечена «не для боевого использования» и правит только локальную демо-БД.

| Инструмент | Зачем |
|---|---|
| произвольное число рефералов, `+1` / `+5` | проверка любого места лестницы без накрутки вручную |
| `open` / `claim` превью по каждому скиллу | прогон анимаций открытия и активации **без изменения состояния** |
| `выдать` / `сброс` по одному скиллу | повторная проверка сценария активации точечно |
| «Все скиллы разлочены» | скриншоты и презентация полного дерева |
| «Reduce motion» | переключение статичного режима без перезагрузки |
| сырые данные + «Применить JSON» | экспорт/импорт состояния для регресс-тестов |
| вход под чужим узлом, тест-ссылка, сброс атрибуции, полный сброс | сценарии атрибуции |
| журнал событий | `opened` / `claimed` с таймстампами и кодом узла — видно, что claim не дублируется |

`?reduce=1` — статичный режим (эквивалент `prefers-reduced-motion: reduce`): дерево,
активация скиллов и покупка билета работают, победная анимация упрощается до смены состояния.

Тестовые карты чекаута: `4242 4242 4242 4242` — успех, `4000 0000 0000 0002` — отказ.

Сценарий приёмки реферала: открыть `?ref=КОД1` (или `?startapp=КОД1`) → оплатить
картой успеха → у `КОД1` счётчик +1, узлы дерева и тир обновляются без перезагрузки;
оплата картой отказа счётчик не двигает; повторная оплата тем же покупателем
не создаёт вторую запись.

## Экономика

Правится в двух массивах `index.html`: `TIERS` — лестница наград (`n` — порог,
`label` — награда, `skill`/`line` — игровая подача), `TICKETS` — тарифы
(`price: null` показывает «уточняется»). Разбивка скиллов по ветвям — `BRANCHES`.
